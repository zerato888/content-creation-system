## En una línea

Desde el principio, **dos servidores de Discord separados**: uno de clientes (donde también está el equipo, porque es parte de la entrega) y otro **solo del equipo**. En el del equipo: una **categoría por área** (producto, operaciones, ventas) con su chat y un general para todos; **canales que reciben automatizaciones** (agendas de cada setter desde Calendly, archivos subidos a la carpeta de cada editor, pagos de Stripe o PayPal, avisos de clientes por vencer) con etiquetas que llegan al teléfono; y **roles por área** más founder y administrador, con categorías privadas para que cada área vea solo lo suyo. El servidor funciona como una base de datos que dispara acción inmediata.

## Recorrido de la clase

| Min | Idea |
|---|---|
| 00:00 | Se puede tener un solo servidor para clientes y equipo, pero con varios clientes y equipo grande no es cómodo: hay que cuidar mucho los permisos para que no se filtre información al cliente. |
| 00:42 | Recomendación: **dos servidores desde el principio**. Uno para clientes (con el equipo, porque es parte de la entrega) y otro solo para ustedes y el equipo. |
| 00:55 | Crear servidor: "para un club o comunidad", foto y nombre (ejemplo: "agencia X team"). Aplica todo lo del Discord de clientes. |
| 01:30 | **Categorías por área**: producto, operaciones, ventas (y las que tenga cada negocio). |
| 02:02 | Dentro de cada una, un **chat del área** para no irse a WhatsApp y que cada conversación quede con quien corresponde. Además un **general** con todo el equipo para lo que cruza áreas. |
| 02:59 | **Categoría de agendas**: un canal por setter (ejemplo: "agenda Juan", "agenda Pedro"). Una automatización conectada a Calendly publica cada llamada agendada. Las agendas de los clientes, en cambio, van en el servidor de clientes. |
| 03:39 | El setter puede dejar en ese canal un dato útil antes de la llamada (algo que salió en el chat de Instagram). |
| 04:00 | **Editores**: una categoría con un canal por editor. Cuando se sube un archivo a su carpeta de Drive llega una notificación que lo **etiqueta**, así le suena en el teléfono. Otra notificación cuando lo mueve a la carpeta de terminado. |
| 04:46 | **Pagos**: conectar Stripe o PayPal para avisar cuando entra un pago a quienes tengan que saberlo. |
| 05:03 | **Roles**: founder y administrador "base siempre"; después **un rol por área** (producto, operaciones, ventas). |
| 05:36 | **Categorías privadas por área**: producto solo visible para rol producto y administrador. Un director comercial puede tener administrador por su jerarquía; un closer no ve producto. |
| 06:12 | Motivo doble: privacidad entre departamentos y **no distraer** a quien no le importa lo del otro. |
| 06:32 | Usan el servidor "como una base de datos" a la que llegan automatizaciones de cada área: aviso de que a un cliente le falta una semana para vencer, todas las agendas, los pagos nuevos. |
| 07:02 | Las notificaciones y etiquetas les permitieron "tomar acción de manera inmediata" en tareas que antes se les pasaban. |
| 07:23 | "La imaginación es el límite": es una base para seguir sumando. |
